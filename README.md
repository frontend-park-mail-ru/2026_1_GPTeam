# 2026_1_GPTeam

Делаем финансовый планировщик (Money First)

[наш деплой](https://money-first.ru/)

[репозиторий бэк](https://github.com/go-park-mail-ru/2026_1_GPTeam)

### Продуктовые требования:
- Авторизация с валидацией.
- Регистрация с валидацией.
- Бюджет (просмотр: фактический и планируемый).
- Баланс (просмотр).
- Профиль пользователя.
- Категория транзакции (создание, просмотр, изменение, удаление).
- Транзакция (создание, просмотр, изменение, удаление).
- Счет (создание, просмотр, изменение, удаление).
- Поиск по транзакциям (фильтрация по категории, типу счёта, приход/расход, дате).
- Бюджет (изменение: пересчет фактического при добавлении/удалении транзакции, редактирование планируемого).
- Отчеты о потраченных средствах за период по категориям.
- Добавление пользователей к счету.
- Импорт и экспорт в CSV.

### Технические требования:
- Деплой.
- Интеграция с бекендом. Присутствует кросс-доменное взаимодействие и настроен CORS.
- SPA.
- Используется модульный и компонентный подход, используются шаблонизаторы.
- Сессия пользователя сохраняется даже при перезагрузке браузера.
- Во всех формах присутствует валидация данных (для валидации используется js). Любой невалидный ввод должен обозначаться сообщением об ошибке.
- Есть линтер (golangci-lint + govulncheck).
- API составлено и задокументировано, в модулях вашего приложения также присутствует JSDoc-документация.
- Ваш сервис отдаёт и принимает данные в формате json.
- Ваш код написан с использованием синтаксиса ES6-модулей, ваш код переписан на TypeScript и настроен транспайлинг кода с помощью babel. Вы собираете бандл через webpack, rollup или любой другой Bundler.
- В ваших проектах есть правильно работающий роутинг, работают переходы по страницам и меняется адрес в адресной строке браузера.
- Вы используете БЭМ или другую методологию написания CSS, а также вы используете pre или post CSS-процессоров.
- Ваше приложение может запускаться и работать offline.
- Ваше приложение написано с чистой архитектурой (есть деление на usecase, delivery, repository).
- Ваши тесты написаны с использованием gomock (+sqlmock для sql субд).
- В вашем проекте настроен логгер, который пишет все необходимые логи.
- В вашем проекте есть защита от XSS и CSRF и sql инъекций.
- В вашем проекте есть профиль и работает загрузка аватарок.
- Адаптируйте ваши приложения для работы на мобильных устройствах и планшетах.
- Ваш проект содержит минимум 4 сервиса (главный, авторизация, файловый сервис, ИИ сервис). Все запросы поступают на главный микросервис, а потом расходятся на остальные микросервисы.
- Ваши сервисы общаются друг с другом по grpc.
- У вас есть метрики ошибок, хитов, таймингов всех запросов по урлам и методам во всех сервисах, цпу, памяти и диска ваших машин. Все эти метрики должны быть на одном дашборде в графане.
- Ваше приложение должно раздаваться nginx'ом.
- Должен быть настроен HTTP/2, https, кэширование статики.
- Во время сборки необходимо оптимизировать ваше приложение: сжимать стили и скрипты, оптимизировать изображения.
- API вашего проекта располагается на том же домене, что и фронтенд по пути /api/ и проксируется через nginx.
- Ваши сервисы деплоятся автоматически через CI после успешного прогона тестов и линтера.
- В проекте используется easyjson для сериализации/десериализации json.
- Ваш проект покрыт тестами на 60%. (Команды для запуска есть в Makefile).

Coverage: 60.5%

## Запуск

Сначала необходимо собрать проект командой 
```
npm run build
```
Запуск проекта через `docker-compose.yaml`.
Требует наличия `docker-compose.yaml` из репозитория бэкенда.
Требует наличия сертификатов для tls.
